# Портал корпоративных мероприятий Colvir

Веб-приложение для записи сотрудников на внутренние мероприятия, тимбилдинги,
Speaking Club, книжный клуб и Random Coffee.

Стек: React 19 + Vite (фронтенд), Express + PostgreSQL (бэкенд),
аутентификация — Active Directory через LDAP.

---

## Что изменилось при переносе в production

До переноса приложение было прототипом с двумя принципиальными ограничениями,
которые делали его непригодным для корпоративной эксплуатации:

| Было | Стало |
| --- | --- |
| Все данные в `localStorage` браузера — каждый сотрудник видел только свои записи | PostgreSQL: мероприятия, участники, команды, оценки и уведомления общие для всех |
| `/api/auth/ad/login` не проверял пароль: любой email нужного домена + любой пароль = вход | Реальный bind к контроллеру домена через `ldapts`, отдельно паролем пользователя |
| Самодельный `token: ad_jwt_token_${Date.now()}`, хранимый на клиенте | Подписанный JWT в httpOnly-cookie + отдельный refresh-токен |
| Права администратора по PIN-коду `2026` и списку email в коде клиента | Роль вычисляется сервером из атрибута `memberOf` Active Directory |
| `SUPER_ADMIN_EMAIL` с личным gmail, зашитый в бандл | Удален; персональных адресов в исходниках нет |
| Описание мероприятия выводилось через `dangerouslySetInnerHTML` без очистки | Санитизация DOMPurify при записи на сервере и при выводе на клиенте |
| «Все попытки логируются службой безопасности» — но логирования не было | Таблица `auth_audit_log` + вывод в stdout для сборщика логов |
| Заголовок `X-Remote-User` принимался от кого угодно | Принимается только с адресов из `SSO_TRUSTED_PROXIES`, SSO по умолчанию выключен |

## Архитектура

```
server/
  config/env.ts          валидация конфигурации; отказ старта при небезопасных значениях
  db/
    migrations/*.sql     схема базы
    migrate.ts           идемпотентный запуск миграций под advisory-блокировкой
    seed.ts              демо-наполнение (опционально)
    pool.ts              пул соединений PostgreSQL
  auth/
    directory.ts         LDAP-каталог (production) и файловый каталог (разработка)
    roles.ts             вычисление роли из memberOf
    tokens.ts            подпись JWT и установка httpOnly-cookie
    trusted-proxy.ts     проверка источника SSO-заголовка по IP/CIDR
    middleware.ts        requireAuth / requireAdmin
    audit.ts             журнал попыток входа
    routes.ts            /api/auth/*
  routes/api.ts          /api/* — данные портала
  services/              работа с базой
  app.ts                 helmet, CORS, rate limit, HTTPS
  index.ts               точка входа
src/
  api/client.ts          обертка над fetch с автообновлением сессии
  context/AuthContext    состояние сессии
  context/AppContext     данные портала (запросы к API)
  utils/eventCategories  человекочитаемые названия категорий (общие для карточки и админки)
  utils/themes           описание тем: баннер и тег подборки
```

## Разделы интерфейса

| Раздел | Кто видит | Назначение |
| --- | --- | --- |
| Дайджест | все | Список мероприятий; при активной теме сверху баннер и подборка |
| Random Coffee | все | Запись на 15-минутные слоты |
| Чат | все | Постоянный раздел с тематическими группами (`chat`) |
| Мои записи | все | Личные регистрации |
| Сформированные группы | администраторы | Команды и выгрузка списков |
| Панель администратора | администраторы | Мероприятия, CMS, слоты, аналитика |

Внешних картинок в шапках разделов нет. Шапку Random Coffee рисует
`RandomCoffeeIllustration.tsx` — инлайновый SVG в фирменной синей палитре;
раньше там стояло фото с `images.unsplash.com` под темным градиентом, которое в
закрытой сети просто не загрузилось бы. Анимации (пар над чашками, точки
диалога) лежат в `src/index.css` и выключаются по `prefers-reduced-motion`.

В русских текстах буква «е» пишется без точек — правило общее для строк
интерфейса, комментариев и документации проекта.

## Оформление и праздничные темы

Тема **общая для компании**: ее переключает администратор во вкладке
«Оформление» панели управления, остальные сотрудники переключателя не видят —
только результат. Тема хранится на сервере (`app_settings`), клиент забирает ее
при загрузке и опрашивает `GET /api/theme` раз в 45 секунд, поэтому смена
доезжает до уже открытых вкладок без перезагрузки.

**Тема не перекрашивает интерфейс.** Кнопки, бейджи, прогресс-бары, активный
пункт навигации — всегда фирменный синий `#1560AA`, независимо от того, какая
тема включена. Раньше акцент подменялся под тему через `data-theme`; это
отменено, и никакой элемент больше не завязан на активную тему.

Тема влияет ровно на два места:

| Что | Где | Поведение |
| --- | --- | --- |
| Баннер | вверху дайджеста | Изображение из `src/assets/themes/` + текст из CMS |
| Подборка мероприятий | под баннером | Карточки с `themeTag` активной темы |

### Баннер

`ThemeBanner.tsx` рендерит карточку с изображением и слоем текста поверх —
без градиентов, блюра и декоративных иконок. Файлы:

| Тема | Файл | Размер | Цвет неба |
| --- | --- | --- | --- |
| Новый год | `colvir-mountain-newyear.jpg` | 1800×617, 125 КБ | `#96B7E4` |
| Весна | `colvir-mountain-spring.jpg` | 1800×617, 123 КБ | `#C5D6F2` |
| День рождения | `colvir-mountain-birthday.jpg` | 1800×638, 110 КБ | `#D2E2F9` |

Текста в самих файлах нет: заголовок и подпись выводятся HTML-слоем и
редактируются в админке, на вкладке «Редактор текстов» (ключи
`themeBanner<Тема>Title` и `themeBanner<Тема>Subtitle`, миграция 010). Раньше
текст был впечатан в картинку, и поменять формулировку можно было только
перерисовав файл.

Баннер — карточка с отступами и скруглением, высотой 240px, а не полоса во всю
ширину. Картинка прижата к левому краю и масштабируется по высоте: при
соотношении сторон ~2.9:1 растянутая по ширине она обрезалась бы по вертикали
почти на треть и срезала вершину горы. Свободная часть справа заливается цветом
неба этой темы (колонка выше), а правый край картинки растушевывается в эту
заливку — стыка не видно. Цвет у каждой темы свой: новогоднее небо заметно
темнее остальных, и одна общая заливка дала бы видимую границу.

При замене файла держите гору в левой трети кадра и возьмите новый цвет неба
пипеткой с правого края — он задается в `src/utils/themes.ts`.

На экране уже `sm` баннер складывается: полоса с картинкой сверху, текст под
ней. Поверх картинки на телефоне текст ставить некуда — гора занимает почти всю
ширину.

Крестик скрывает баннер на сессию (`sessionStorage`, не `localStorage`): в новой
сессии он возвращается. Смена темы тоже возвращает баннер — закрытие относится к
конкретной теме.

У классической темы баннера нет вовсе.

### Подборка мероприятий

Попасть в подборку можно двумя равноправными способами — достаточно любого:

| Способ | Где задается | Что дает |
| --- | --- | --- |
| Поле `themeTag` | выпадающий список «Праздничная подборка» в форме события | явная привязка к одной теме |
| Хэштег | поле «Хэштеги» там же | то же самое, но без захода в список |

Хэштеги тем (`src/utils/themeTags.ts`):

| Тема | Хэштеги |
| --- | --- |
| Новый год | `#новыйгод`, `#colvirnewyear`, `#newyear` |
| Весна | `#colvirspring`, `#весна`, `#spring` |
| День рождения | `#деньрождения`, `#colvirbirthday`, `#birthday` |

Хэштег сравнивается **целиком**, а не по вхождению подстроки: первая версия
подборки искала «новый год» внутри тегов, и мероприятие с тегом «новый формат»
попадало в новогоднюю подборку. Перед сравнением тег приводится к нижнему
регистру, из него убираются решетка, пробелы, дефисы и подчеркивания, а «ё»
заменяется на «е» — поэтому `#Новый Год`, `новый-год` и `новыйгод` это один и
тот же хэштег.

В поле ввода хэштеги разделяются запятой или пробелом. Пробел не может
одновременно быть разделителем и частью хэштега, поэтому правило зависит от
решеток: есть решетки — новый хэштег начинается с них, и `#День Рождения`
остается одним хэштегом из двух слов; решеток нет — разделителем работает
пробел, и `деньрождения квиз` дает два хэштега.

Служебные теги (категория и «Команды»/«Индивидуально») форма проставляет сама и
в поле не показывает. Больше десяти хэштегов на мероприятие форма не берет,
сервер режет список на двенадцати тегах — форма не защита, запрос можно
отправить и мимо нее.

Карточки — обычный `EventCard` без изменений, с тем же фирменным синим, что и в
основном списке. Если подходящих мероприятий нет, секция не показывается вовсе.

### Переменные акцента

| Переменная | Назначение |
| --- | --- |
| `--color-accent` | кнопки, активный пункт навигации, прогресс-бары |
| `--color-accent-hover` | состояние `hover` |
| `--color-accent-soft` | фон бейджей и подложек |
| `--color-accent-light` | светлая подложка блоков |

Переменные оставлены, хотя смена акцента по теме отменена: они убирают хардкод
`bg-[#1560AA]` (было 396 вхождений в 22 файлах) и держат цвет в одном месте.
Завязки на тему в них нет.

Заголовок и подпись каждого праздничного баннера правятся в редакторе CMS,
блок «Баннеры праздничных тем». Прежние склеенные строки вида
«Заголовок: подпись» (`holidayBanner*Text`) интерфейсом не используются, но из
базы не удалены — на случай, если формулировки оттуда понадобится перенести.

## Чат и тематические группы

Группы **открытые**: зайти, читать и писать может любой сотрудник, списка
участников нет — поэтому нет и таблицы членства, и проверок доступа. Заводит и
закрывает группы **только администратор**, прямо в разделе «Чат»; сервер
проверяет роль через `requireAdmin`, интерфейс лишь прячет кнопки.

Идентификатор канала получается транслитерацией названия: «Книжный клуб» →
`knizhnyy-klub`. При совпадении добавляется суффикс (`-2`), а если
транслитерировать нечего — подставляется `kanal-<случайный суффикс>`.

**Закрытие группы не удаляет переписку.** У `chat_messages` внешний ключ на
канал стоит с `ON DELETE CASCADE`, то есть удаление канала унесло бы всю
историю. Вместо этого проставляется `archived_at`: группа пропадает из списка,
писать в нее больше нельзя, сообщения остаются в базе. Общий канал `general`
закрыть нельзя — в него уходят сообщения без явного канала.

| Метод | Маршрут | Кто может |
| --- | --- | --- |
| GET | `/api/chat/channels` | все |
| POST | `/api/chat/channels` | администратор |
| POST | `/api/chat/channels/:id/archive` | администратор |
| GET | `/api/chat/messages?channelId=…` | все |
| POST | `/api/chat/messages` | все |

### Упоминания сотрудников

«@» в поле ввода открывает подсказку с коллегами, выбор — стрелками и Enter или
мышью. Упомянутый получает личное уведомление, а его имя в сообщении
подсвечивается: свое — заметнее, чужие — акцентным цветом.

Упоминания хранятся отдельной таблицей `chat_mentions`, а не разбором текста при
показе: разбор по имени был бы ненадежен из-за тезок, смены фамилии и знаков
препинания сразу после имени — подсветка и уведомления начали бы расходиться.
Клиент присылает идентификаторы, сервер проверяет их и молча отбрасывает
неизвестные, так что подделанный запрос не создаст уведомлений в никуда.
Упоминание самого себя и повторы одного человека уведомлений не порождают.

Подсказка ищет **среди тех, кто хотя бы раз входил в портал**. Остальных
упоминать бессмысленно: учетной записи в базе еще нет, уведомление им прийти
некуда. Как только человек войдет первый раз, он появится в подсказке.

Заодно исправлено: лента администратора показывала только записи на мероприятия,
поэтому упоминание администратора и его пара по Random Coffee до него не
доходили. Теперь в его ленте и общие, и личные уведомления.

### Изображения в сообщениях

Прикрепляется один файл до 20 МБ: PNG, JPEG, GIF или WEBP. Сообщение может
состоять из одной картинки, подпись необязательна.

**Файлы лежат на диске**, каталог задается через `UPLOADS_DIR`, в базе только
метаданные. Двадцатимегабайтные картинки в `bytea` попадали бы в WAL и в каждый
дамп, а выборка сообщений тянула бы блобы вместе с текстом. Каталог проверяется
на старте: если он недоступен для записи, сервер не поднимется — иначе об этом
узнал бы первый сотрудник, отправивший картинку.

Что важно при развертывании: каталог должен быть **вне** каталога приложения и
переживать переустановку, а при нескольких репликах — быть общим для всех
(сетевая шара или монтируемый том). Иначе картинка, загруженная через одну
реплику, не откроется через другую. Резервное копирование каталога — отдельно от
дампа базы.

**Проверки при загрузке:**

- Тип определяется **по сигнатуре файла**, а не по расширению и не по
  `Content-Type` от клиента: HTML со скриптом, названный `cat.png`, отклоняется.
- **SVG не поддерживается** намеренно — он умеет исполнять скрипты, и
  встроенный в него JavaScript выполнился бы в домене портала.
- Имя файла на диске генерируется сервером, исходное хранится отдельно и только
  для показа; управляющие символы из него вычищаются.
- Отдача идет маршрутом под аутентификацией с `X-Content-Type-Options: nosniff`
  и типом из базы — переписка компании не открывается по прямой ссылке без входа.
- Если сообщение не удалось записать уже после сохранения картинки (например,
  группу закрыли, пока файл загружался), файл удаляется — сирот в хранилище не
  остается.

Чего пока нет: сервер не уменьшает картинки, в ленту отдается оригинал. При
активной переписке с крупными файлами стоит добавить генерацию превью
(`sharp`) — сейчас нагрузку сдерживает только отложенная загрузка изображений в
браузере.

Чего еще нет: счетчика непрочитанного и уведомлений о новых сообщениях в
группе. С одним каналом это не мешало, с десятком станет заметно — понадобится
отметка последнего прочитанного на пару «пользователь и канал». Лента
обновляется поллингом; если каналов станет много, узким местом станет он.

## Random Coffee

Работает циклами:

1. Администратор открывает цикл — дату встреч и срок записи.
2. Сотрудник отмечает **все** удобные слоты, а не один.
3. По дедлайну сервер разбивает участников на пары так, чтобы время подходило
   обоим, и отправляет обоим личное уведомление.

Это решает исходную проблему «выбрал время, а коллега в него не может»: время
встречи выбирает не человек до подбора, а система после — из общего для двоих.

**Алгоритм** (`buildMatchPlan` в `server/services/coffee.ts`) — жадный по числу
вариантов: первым получает пару тот, у кого меньше всего возможных партнеров.
Ранее встречавшиеся пары не повторяются, пока есть альтернатива. При нечетном
числе участников последний присоединяется третьим к подходящей встрече.
Оставшиеся без пары возвращаются списком, чтобы администратор видел картину.

**Планировщик** (`server/scheduler.ts`) раз в минуту закрывает просроченные
циклы и рассылает напоминание «пора на кофе-брейк» перед началом слота.
Отключается через `SCHEDULER_ENABLED=false`, если задачи выносятся в CronJob.
При нескольких репликах дубликатов не будет: подбор защищен статусом цикла,
напоминания — полем `reminder_sent_at`.

**Уведомления** приходят в портал обоим участникам. Исходящей доставки в проекте
нет — для рассылки за пределы портала понадобится SMTP или интеграция с
корпоративным мессенджером eXpress.

Прежняя реализация подбирала коллегу в браузере одного человека, пару никуда не
сохраняла и при пустом слоте подставляла пять захардкоженных «сотрудников» —
все это удалено.

Музыкального плеера и плейлиста в продукте нет (убраны миграцией
`003_drop_holiday_music.sql`).

## Запуск на корпоративном сервере

### 1. База данных

```bash
createdb colvir_events
createuser colvir_events --pwprompt
psql -c "GRANT ALL PRIVILEGES ON DATABASE colvir_events TO colvir_events;"
```

### 2. Конфигурация

```bash
cp .env.example .env
```

Обязательно заполните:

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `JWT_SECRET` | сгенерируйте: `openssl rand -base64 48` |
| `LDAP_URL` | `ldaps://dc01.colvir.com:636` |
| `LDAP_BIND_DN` / `LDAP_BIND_PASSWORD` | сервисная учетная запись для поиска в каталоге |
| `LDAP_SEARCH_BASE` | `DC=colvir,DC=com` |
| `AD_DOMAIN` | `COLVIR.COM` |
| `AD_ADMIN_GROUPS` | группа AD, дающая права администратора портала |

`.env` не коммитится — он в `.gitignore`.

Сервер **не стартует**, если:

* `JWT_SECRET` пустой, короче 32 символов или равен значению из примера;
* в production не заданы параметры LDAP;
* `LDAP_URL` использует незашифрованный `ldap://` без явного `LDAP_ALLOW_PLAINTEXT=true`;
* не задан `AD_ADMIN_GROUPS`;
* при `NODE_ENV=production` задан `AUTH_DEV_DIRECTORY_FILE`;
* `SSO_ENABLED=true`, но не перечислены `SSO_TRUSTED_PROXIES`.

### 3. Сборка и запуск

```bash
npm ci
npm run build        # фронтенд в dist/, сервер в dist-server/
npm start            # node dist-server/server.mjs
```

Миграции применяются автоматически при старте. Если схемой управляет CI,
поставьте `RUN_MIGRATIONS_ON_START=false` и запускайте `npm run migrate` отдельно.

Демо-наполнение (не нужно в production):

```bash
npm run seed          # только если база пуста
npm run seed -- --force
```

### 4. Reverse-proxy и HTTPS

Node слушает `127.0.0.1:3000` и **не должен быть доступен из корпоративной сети
напрямую** — иначе SSO-заголовок можно выставить в обход прокси.

Готовый пример конфигурации: [`deploy/nginx.conf`](deploy/nginx.conf).
Сертификат — от внутреннего CA компании либо Let's Encrypt, если домен
резолвится публично.

### 5. Docker

```bash
docker build -t colvir-event-portal .
docker run -d --name colvir-events -p 127.0.0.1:3000:3000 --env-file .env colvir-event-portal
```

## Аутентификация Active Directory

### Вход по логину и паролю

`POST /api/auth/ad/login` c `{ email, password }`:

1. Проверяется домен корпоративной почты (`AD_ALLOWED_EMAIL_DOMAINS`).
2. Сервисной учетной записью выполняется поиск сотрудника по
   `LDAP_USER_SEARCH_FILTER`; значение логина экранируется по RFC 4515,
   так что инъекция в фильтр невозможна.
3. Проверяется флаг `ACCOUNTDISABLE` в `userAccountControl`.
4. Выполняется **отдельный bind паролем пользователя** — это и есть проверка пароля.
   Пустой пароль отклоняется до обращения к каталогу: в LDAP пустой пароль
   означает анонимный bind, который завершился бы успешно.
5. Роль вычисляется из `memberOf`.
6. Выдается пара токенов в httpOnly-cookie.

Ответ при неверном пароле и при несуществующем логине одинаков — эндпоинт
нельзя использовать для перебора учетных записей домена.

### Сквозной вход (Kerberos / NTLM)

Работает только за корпоративным reverse-proxy и только при `SSO_ENABLED=true`.

Прокси выполняет SPNEGO-негошиэйшн и передает имя пользователя в заголовке
`X-Remote-User`. Сервер принимает заголовок, **только если `req.socket.remoteAddress`
входит в `SSO_TRUSTED_PROXIES`** — это реальный адрес отправителя пакета, его
нельзя подделать. Профиль и группы все равно читаются из каталога, а не из заголовка.

В `deploy/nginx.conf` заголовок принудительно очищается (`proxy_set_header X-Remote-User "";`)
и заполняется только в блоке `/api/auth/ad/sso` после успешной проверки билета.

### Роли

Роль администратора выдается членством в группе из `AD_ADMIN_GROUPS`
(сравнение по CN, регистр не важен). Чтобы выдать или отозвать права,
измените состав группы в домене — портал не хранит собственных списков.

`POST /api/auth/ad/sync` перечитывает профиль и группы и перевыпускает токены,
поэтому отзыв прав применяется без ожидания истечения сессии.

### Журнал безопасности

Каждый вход, выход, обновление сессии и отказ в доступе пишется в
`auth_audit_log` (тип события, UPN, результат, причина, IP, User-Agent) и
дублируется в stdout.

```sql
-- неудачные попытки входа за сутки
SELECT occurred_at, upn, reason, ip_address
FROM auth_audit_log
WHERE NOT success AND occurred_at > now() - interval '1 day'
ORDER BY occurred_at DESC;
```

## Бесплатный хостинг: показать портал коллегам по ссылке

Портал можно поднять в интернете бесплатно и без банковской карты. Нужны две
площадки: **Neon** для базы данных и **Render** для самого приложения.
Занимает минут двадцать.

### 1. База данных на Neon

1. Зарегистрироваться на neon.com, создать проект (регион лучше европейский).
2. Скопировать строку подключения — она выглядит как
   `postgresql://пользователь:пароль@ep-что-то.neon.tech/neondb?sslmode=require`.
   Отложить, понадобится на следующем шаге.

Neon бесплатно дает 0,5 ГБ и не имеет срока годности. База засыпает после пяти
минут простоя и просыпается за пару секунд при первом запросе.

### 2. Приложение на Render

1. На render.com выбрать **New → Blueprint** и указать этот репозиторий.
   Render сам найдет файл `render.yaml` в корне и подставит все настройки.
2. Он спросит единственное значение — **DATABASE_URL**. Вставить туда строку
   из Neon.
3. Нажать создание и подождать первую сборку — она идет несколько минут.

Дальше приложение само применит миграции и зальет демо-мероприятия. Адрес будет
вида `https://colvir-event-portal.onrender.com`. Учетные записи те же, что на
локальном стенде: `a.admin@colvir.com` и остальные, пароль `ColvirDemo2026`.

### Что нужно знать про бесплатный тариф

| Особенность | Что это значит на практике |
| --- | --- |
| Сервис засыпает после 15 минут простоя | Первый заход после паузы грузится около минуты. Дальше работает как обычно |
| Нет постоянного диска | Поэтому картинки чата хранятся в базе (`UPLOADS_DRIVER=database`), а не файлами. Размер картинки ограничен 3 МБ, чтобы не съесть бесплатные 0,5 ГБ |
| База Neon засыпает через 5 минут | Первый запрос будит ее за пару секунд |

### Важно про безопасность

Это **демо в открытом интернете**: адрес доступен всем, у кого есть ссылка, а
пароль демо-учетных записей лежит в этом README. Внутри только выдуманные
мероприятия и сотрудники, но:

- не выкладывайте туда настоящие данные компании;
- не давайте ссылку шире, чем нужно для показа;
- Active Directory здесь не используется вовсе — из интернета контроллер домена
  недоступен, поэтому вход идет по файлу с учетными записями. Для настоящей
  установки внутри компании это недопустимо, и сервер в production-режиме сам
  откажется так стартовать.

Настоящая установка с доменной аутентификацией — раздел «Запуск на корпоративном
сервере» ниже.

## Демо-стенд: потыкать приложение целиком

Нужен только Docker. Ни Active Directory, ни отдельной базы, ни настройки:

```bash
docker compose -f docker-compose.demo.yml up --build
```

Открыть http://localhost:3000. Учетные записи — пароль у всех `ColvirDemo2026`:

| Логин | Роль | Что видно |
| --- | --- | --- |
| `a.admin@colvir.com` | администратор | Панель управления, оформление, циклы Random Coffee, создание групп в чате |
| `i.ivanov@colvir.com` | сотрудник | Обычный интерфейс |
| `e.smirnova@colvir.com` | сотрудник | Второй сотрудник — удобно проверять чат и упоминания |
| `m.sokolov@colvir.com` | сотрудник | Третий, чтобы Random Coffee было кого с кем сводить |

Стенд поднимает Postgres, применяет миграции и заливает демо-мероприятия при
первом старте. Данные переживают перезапуск (тома `demo-db` и `demo-uploads`).
Сбросить все и начать заново:

```bash
docker compose -f docker-compose.demo.yml down -v
```

Что удобно проверить: сменить оформление в админке и увидеть, как у сотрудника
в другом окне через минуту появится баннер и подборка; открыть цикл Random
Coffee и отметить слоты разными пользователями; кинуть картинку в чат и
упомянуть коллегу через «@».

### Если http://localhost:3000 не открывается

Сначала посмотрите, что со стендом:

```bash
docker compose -f docker-compose.demo.yml ps      # состояние контейнеров
docker compose -f docker-compose.demo.yml logs app --tail=50
```

| Что видно | Причина и что делать |
| --- | --- |
| `no configuration file provided` | Команда запущена не из каталога `colvir-event-portal` |
| `unknown shorthand flag` или ошибка на `condition:` | Установлен старый `docker-compose` v1. Нужен Compose v2: команда пишется через пробел — `docker compose`, а не `docker-compose` |
| `port is already allocated` | Порт 3000 занят — например, локально запущен `npm run dev`. Остановите его или поменяйте порт в `ports` |
| Контейнер `app` в состоянии `Restarting` | Смотрите `logs app`: обычно это база не поднялась или каталог загрузок недоступен для записи |
| `Не удалось подключиться к базе данных` | База еще стартует. С `restart: unless-stopped` приложение поднимется само через несколько секунд |
| Страница пустая, в консоли браузера 404 на `/assets/...` | Образ собран без клиента. Пересоберите: `docker compose -f docker-compose.demo.yml up --build --force-recreate` |
| Сборка падает на `npm ci` | Проверьте, что рядом лежит `package-lock.json` и он не изменялся вручную |

Полный сброс, если стенд запутался:

```bash
docker compose -f docker-compose.demo.yml down -v
docker compose -f docker-compose.demo.yml up --build
```

**Это не production.** Пользователи лежат в файле с известным паролем, стенд
работает по http без Active Directory. Поэтому он и запускается с
`NODE_ENV=development`: в production-режиме сервер намеренно откажется стартовать
с файловым каталогом вместо контроллера домена. Не выставляйте этот стенд в сеть,
доступную посторонним, — порт специально привязан к `127.0.0.1`.

## Локальная разработка

Контроллер домена для разработки не нужен — есть файловый каталог с
scrypt-хешами паролей. В production он запрещен проверкой конфигурации.

```bash
createdb colvir_events_dev

cat > .env <<'EOF'
NODE_ENV=development
DATABASE_URL=postgres://localhost:5432/colvir_events_dev
JWT_SECRET=локальный-секрет-минимум-32-символа-для-разработки
AD_DOMAIN=COLVIR.COM
AD_ADMIN_GROUPS=Colvir-Event-Managers
AUTH_DEV_DIRECTORY_FILE=./dev-directory.json
COOKIE_SECURE=false
FORCE_HTTPS=false
EOF

npm install
npm run dev:directory -- i.ivanov@colvir.com Пароль123
npm run dev:directory -- a.admin@colvir.com Пароль123 --admin
npm run migrate
npm run seed
npm run dev
```

## Проверки

```bash
npm run lint    # tsc --noEmit, strict mode
npm test        # интеграционные тесты (нужен PostgreSQL)
```

Тесты поднимают приложение целиком и проверяют: отказ при неверном и пустом
пароле, неразличимость ответов для несуществующего логина, выдачу роли по
группе AD, отклонение подделанного SSO-заголовка, запись событий в журнал,
недоступность API без сессии, запрет операций администратора рядовому
сотруднику, вырезание `<script>` и `javascript:` из описания мероприятия,
подстановку email из сессии вместо тела запроса, запрет повторной записи и
отмены чужой записи, видимость данных между разными сессиями, а также работу
праздничного чата и отсутствие удаленных эндпоинтов плейлиста.

База для тестов задается через `TEST_DATABASE_URL`
(по умолчанию `postgres://postgres@localhost:5432/colvir_events_test`).

## Известные ограничения

* **`xlsx` (SheetJS)**. Пакет используется для выгрузки списков участников в
  Excel. Версия в npm-реестре не обновляется и имеет незакрытые уязвимости
  (prototype pollution, ReDoS) — исправления публикуются только на
  `cdn.sheetjs.com`. Выгрузка выполняется в браузере администратора на данных
  из собственной базы, поэтому вектор ограничен, но при первой возможности
  стоит перейти на дистрибутив с cdn.sheetjs.com либо на `exceljs`.
* **Аватары и картинки мероприятий** хранятся как data:URL в базе. Для
  большого числа мероприятий имеет смысл вынести их в объектное хранилище.
* **Обновление данных** происходит по запросу пользователя. Живого обновления
  списка участников (SSE/WebSocket) пока нет.
